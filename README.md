# hl7lib - a from-scratch HL7 v2 parser

Parses HL7 v2 messages (the pipe-delimited format hospitals still run on) into
clean structured data, and explains every segment. Handles ADT (admit/discharge/
transfer) and ORU (lab results), plus a graceful fallback for anything else.

> Synthetic data only. The sample messages are generated by Faker (see
> `hl7lib/generate.py`). Never put real HL7 - which contains real PHI - in a repo.

## What it does

- Parses a raw message into segments -> fields -> repetitions -> components ->
  subcomponents, reading the delimiters the message declares in MSH-1/MSH-2.
- `parse_adt()` pulls the message header (MSH), patient (PID), and visit (PV1).
- `parse_oru()` pulls the header, patient, order (OBR), and each result (OBX),
  grouping observations under their order.
- `annotate()` produces a labelled, field-by-field breakdown ("PID-5 = Patient
  Name = Scott^Chad^T") - the "explain each segment" deliverable.
- Fails clearly on garbage (no MSH, truncated header) and degrades gracefully on
  missing fields (returns "" instead of crashing).

## Run it

```powershell
python -m venv .venv ; .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

python generate_samples.py                       # writes data/sample/*.hl7
python parse_message.py --input data/sample/adt_a01.hl7
python parse_message.py --input data/sample/oru_r01.hl7 --annotate
pytest                                            # 23 tests
```

## How the code is organised

```
hl7lib/
├── parser.py     The core: Message, Segment, parse(). All the delimiter logic.
├── fields.py     Human-readable segment/field names + annotate().
├── adt.py        parse_adt() + the shared MSH/PID readers.
├── oru.py        parse_oru() with OBR/OBX grouping.
└── generate.py   Synthetic ADT/ORU message generator (Faker).
parse_message.py  CLI: .hl7 file -> JSON (or --annotate).
generate_samples.py
tests/            pytest: parser, adt, oru, malformed, round-trip.
```

## Why build the parser instead of pip installing one

Libraries exist (hl7apy, python-hl7), and a real job would often reach for a
maintained one. Writing the parser from scratch means understanding HL7 down
to the encoding characters, which is what an integration task actually tests.

## Honest limitations

- We parse the ER7 (pipe-delimited) encoding, not XML-encoded HL7 v2.
- We don't process escape sequences (\\F\\ etc.) inside field text - rare in
  practice, and called out where it matters.
- We handle the common segments (MSH, EVN, PID, NK1, PV1, OBR, OBX, DG1, AL1); the
  full standard has hundreds. Adding one is just another entry in `fields.py`.
